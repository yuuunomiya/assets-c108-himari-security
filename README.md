# ミレニアム電子部品株式会社 オンラインストア

同人誌『明星ヒマリと学ぶウェブアプリセキュリティ入門』（C108）の演習用サンプルアプリケーションです。

架空の電子部品ECサイトを題材に、XSS・SQLインジェクション・CSRF・認可の不備・認証/セッション管理といった代表的な脆弱性を、実際に手を動かしながら学べるように作られています。

---

## ⚠️ はじめにお読みください

**このリポジトリには、学習用に脆弱性を再現したコードが含まれています。**

`main` ブランチは本書で扱うすべての脆弱性を**修正済み**の状態です。演習で使う脆弱性は、`vuln/` から始まる章ごとのブランチに再現されています（詳しくは「[ブランチ構成](#ブランチ構成)」を参照してください）。

- **ローカル環境専用です。** インターネットから到達できるサーバーには絶対にデプロイしないでください
- **本番環境の実装の参考にしないでください。** `vuln/` ブランチのコードは、あえて危険な書き方をしています
- **攻撃手法の実践は、このサンプルアプリに対してのみ行ってください。** 自分が管理していないシステムや、書面による明確な許可を得ていないシステムへの攻撃は、不正アクセス禁止法などに抵触する犯罪行為です
- 登録されているメールアドレス・パスワードはすべて演習用のダミーです。

## 動作環境

- macOS / Windows（WSL2上での利用を推奨）/ Linux
- Docker Desktop（または Docker Engine + Docker Compose）
- Git
- ウェブブラウザ（本書はGoogle Chromeを前提に解説しています）

使用技術は Ruby on Rails 8.1 / PostgreSQL 16 / Docker Compose です。

## 起動方法

```bash
git clone https://github.com/yuuunomiya/assets-c108-himari-security.git
cd assets-c108-himari-security
cp .env.example .env
docker compose up --build -d
```

初回はイメージのビルドと依存ライブラリのダウンロードに数分かかります。次のコマンドでログを表示し、`Listening on http://0.0.0.0:3000` のような行が出るまで待ってください（`Ctrl+C` でログ表示だけを終了できます）。

```bash
docker compose logs -f web
```

起動したら、ブラウザで http://localhost:3000 にアクセスしてください。データベースの作成・マイグレーション・初期データ（Seed）の投入は、起動時に自動で実行されます。

## ブランチ構成

本書のサンプルアプリケーションは、Git のブランチによって次の2つの状態を切り替えられます。

- **`main`**：本書で扱うすべての脆弱性を**修正済み**の状態
- **`vuln/chXX-〇〇`**：該当する章で扱う脆弱性**だけ**を再現した状態

| ブランチ | 章 | 扱う脆弱性 |
| --- | --- | --- |
| `vuln/ch04-recon` | 第4章 | 情報漏洩と偵察（デバッグモードの設定不備） |
| `vuln/ch05-xss` | 第5章 | クロスサイトスクリプティング（反射型・格納型） |
| `vuln/ch06-sqli` | 第6章 | SQLインジェクション |
| `vuln/ch07-csrf` | 第7章 | クロスサイトリクエストフォージェリ |
| `vuln/ch08-authz` | 第8章 | 認可の不備（IDOR・マスアサインメント） |
| `vuln/ch09-authn` | 第9章 | 認証・セッション管理の不備 |

演習を始めるときは、各章の冒頭で案内されているブランチに切り替えてから、アプリケーションを起動し直してください。

```bash
git switch vuln/ch04-recon
docker compose up --build -d
```

攻撃を体験し終えたら、`git switch main` で修正済みの状態に戻せます。`main` との差分を確認すれば、どのコードを変えるとその脆弱性が生まれるのかを具体的に見ることができます。

```bash
git diff main..vuln/ch04-recon
```

## 第7章・第9章の準備：hosts ファイルの設定

第7章と第9章では、攻撃者のサイトを模した簡易サーバー（`exploit-examples/` を配信）を使います。SameSite Cookie はポート番号を区別しないため、`localhost` とは別のホスト名でアクセスする必要があります。

hosts ファイルに次の1行を追記してください。

```
127.0.0.1 evil.test
```

**macOS / Linux**

```bash
sudo sh -c 'echo "127.0.0.1 evil.test" >> /etc/hosts'
```

**Windows**

管理者権限でメモ帳を起動し、`C:\Windows\System32\drivers\etc\hosts` を開いて末尾に追記してください。

設定後、攻撃者サイトは http://evil.test:8080 でアクセスできます（Dockerコンテナ側の設定変更は不要です）。この設定は第9章の演習でも使うため、第9章が終わるまで残しておいてください。

## 停止と初期化

```bash
# コンテナを停止する（データは保持される）
docker compose down

# データベースを含めて完全に初期化する（演習の内容はすべて失われます）
docker compose down -v
```

## うまく動かないときは

書籍の付録C（トラブルシューティング）に、よくあるトラブルと対処法をまとめています。あわせて次の点もご確認ください。

- **商品画像が表示されない**：商品画像は外部サービス（placehold.co）から読み込んでいます。オフライン環境では画像が表示されませんが、演習そのものには影響しません
- **初回起動が遅い**：イメージのビルドとGemのインストールで数分かかります。通信量も多いため、安定したネットワーク環境での実行を推奨します
- **`git switch` でブランチを切り替えられない**：演習の中でファイルを編集すると、`error: Your local changes to the following files would be overwritten by checkout` と表示されて切り替えに失敗することがあります。編集内容が不要であれば、`git restore .` で破棄してから切り替えてください
- **ブランチを切り替えたのに挙動が変わらない**：`config/` 以下の設定ファイルは起動時にしか読み込まれません。切り替えたら `docker compose up --build -d` でコンテナを起動し直してください
