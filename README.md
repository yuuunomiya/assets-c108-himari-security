# ミレニアム電子部品株式会社 オンラインストア

同人誌『明星ヒマリのハッキングして学ぶWebアプリケーションにおけるセキュリティ対策』（C108）の演習用サンプルアプリケーションです。

架空の電子部品ECサイトを題材に、XSS・SQLインジェクション・CSRF・認可の不備・認証/セッション管理といった代表的な脆弱性を、実際に手を動かしながら学べるように作られています。

## 動作環境

- macOS / Windows（WSL2上での利用を推奨）/ Linux
- Docker Desktop（または Docker Engine + Docker Compose）
- Git
- ウェブブラウザ（本書はGoogle Chromeを前提に解説しています）

使用技術は Ruby on Rails 8.1 / PostgreSQL 16 / Docker Compose です。

## 起動方法

```bash
git clone https://github.com/yuuunomiya/assets-c108-himari-security.git
cd assets-c108-himari-security
cp .env.example .env
docker compose up --build -d
```

初回はイメージのビルドと依存ライブラリのダウンロードに数分かかります。次のコマンドでログを表示し、`Listening on http://0.0.0.0:3000` のような行が出るまで待ってください（`Ctrl+C` でログ表示だけを終了できます）。

```bash
docker compose logs -f web
```

起動したら、ブラウザで http://localhost:3000 にアクセスしてください。データベースの作成・マイグレーション・初期データ（Seed）の投入は、起動時に自動で実行されます。

## 第7章（CSRF）の準備：hosts ファイルの設定

第7章では、攻撃者のサイトを模した簡易サーバー（`exploit-examples/` を配信）を使います。SameSite Cookie はポート番号を区別しないため、`localhost` とは別のホスト名でアクセスする必要があります。

hosts ファイルに次の1行を追記してください。

```
127.0.0.1 evil.test
```

**macOS / Linux**

```bash
sudo sh -c 'echo "127.0.0.1 evil.test" >> /etc/hosts'
```

**Windows**

管理者権限でメモ帳を起動し、`C:\Windows\System32\drivers\etc\hosts` を開いて末尾に追記してください。

設定後、攻撃者サイトは http://evil.test:8080 でアクセスできます（Dockerコンテナ側の設定変更は不要です）。

## 停止と初期化

```bash
# コンテナを停止する（データは保持される）
docker compose down

# データベースを含めて完全に初期化する（演習の内容はすべて失われます）
docker compose down -v
```

## うまく動かないときは

書籍の**付録C（トラブルシューティング）**に、よくあるトラブルと対処法をまとめています。あわせて次の点もご確認ください。

- **商品画像が表示されない** — 商品画像は外部サービス（placehold.co）から読み込んでいます。オフライン環境では画像が表示されませんが、演習そのものには影響しません
- **初回起動が遅い** — イメージのビルドとGemのインストールで数分かかります。通信量も多いため、安定したネットワーク環境での実行を推奨します
